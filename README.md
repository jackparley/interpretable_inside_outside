# Interpretable inside–outside computation in Transformers

Code and numerical results accompanying the preprint:

> **Stagewise and interpretable emergence of inside-outside computation in Transformer-based language models**  
> Jack T. Parley (2026)  
> [arXiv:2611.14221](https://arxiv.org/abs/2611.14221)

## Overview

We study how Transformer language models learn to predict the last token of sequences generated by a *Varying-Tree Random Hierarchy Model* (VT-RHM), a layered probabilistic context-free grammar with binary and ternary productions. The grammar allows multiple tree topologies for a given terminal sequence. The experiments compare Transformer learning curves with predictions derived from exact inside–outside inference and use linear probes to study the emergence of latent hierarchical representations across network depth and training time.

This repository contains the original research implementations, lightweight command-line interfaces for training and inference, checkpoint probing utilities, and scripts for regenerating selected figures from included numerical results. The saved figure-result files are **not** trained model checkpoints.

## Quick start: reproduce figures

From the repository root, with dependencies installed (see below):

```bash
python -m experiments.plot_learning_curves \
    --data-dir figure_data/training \
    --output figures/learning_curves

python -m experiments.plot_fixed_vs_varying_tree \
    --data-dir figure_data/probes \
    --output figures/fixed_vs_varying

python -m experiments.plot_relative_depth \
    --data-dir figure_data/probes \
    --output figures/relative_depth

for depth in 3 6 12; do
    python -m experiments.plot_latent_probe_accuracy \
        --depth "$depth" \
        --data-dir figure_data/latents \
        --output "figures/latent_probe_depth${depth}"
done
```

Each command saves both PDF and PNG figures. These plots use small cached numerical-result files in `figure_data/`, so **no GPU or model checkpoints are required** for figure regeneration. The latent-probe plotting command uses the corrected depth-6 step-16384 file when available.

The scripts reproduce *selected* paper analyses, not necessarily every panel in the preprint. See [`experiments/README.md`](experiments/README.md) for input schemas and details.

## Installation

Python 3.10+ is recommended; the interface and small tests have been checked on Python 3.13, and the original training code should also be tested in your target environment.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Main dependencies include PyTorch, NumPy, SciPy, scikit-learn, Matplotlib, and Jupyter. Dependency versions are not yet pinned. For GPU training, install a PyTorch build suitable for your accelerator.

Always run the commands from the **repository root**.

## Train a Transformer

A small CPU smoke test:

```bash
python -m rhm_training --preset smoke
```

This uses an `L=3`, `v=8`, `m2=2`, `m3=16` grammar and trains a compact Transformer. Results and the associated configuration manifest are saved under `runs/training_smoke/` (ignored by Git).

Inspect the high-compute reference configuration without executing it:

```bash
python -m rhm_training --preset paper --dry-run
```

The `paper` preset represents **one** large-scale configuration; different paper figures use different architectures, checkpoints and hyperparameters. To save model checkpoints for future probing, supply `--checkpoints` when training. The normal saved training-history `.pt` file should not be assumed to contain model weights.

## Exact inference and Bayes last-token losses

For `L=3`, `v=8`, `m2=2`, `m3=16` and grammar seed `12345678`:

```bash
python -m rhm_inference \
    --samples 200 --v 8 --L 3 --m2 2 --m3 16 \
    --seed-rules 12345678 --sample-seed 42 \
    --known-layers all
```

Change `--known-layers` to one of `bottom-intermediate`, `bottom`, or `bottom-binary`. Outputs go to `runs/bayes_losses/<known-layers>/summary.json` and `samples.csv`.

The reported entropy is normalized by `ln(v)`. The partial-knowledge calculations use ensemble-mean tensors for the unknown layers, following the original implementation; do not interpret these automatically as exact posterior marginalization over unknown grammar realizations. By default, the predictor marginalizes over possible sentence lengths according to the original padding convention; `--fixed-length` changes that conditioning.

## Linear probes of checkpoint representations

The probing interface requires actual model-weight checkpoints **and** a compatible original reference bundle specifying latent targets and probing metadata. For example:

```bash
python -m rhm_probing \
    --reference /path/to/second_third_last_probe_checkpoint_results.pkl \
    --checkpoint /path/to/actual_model_checkpoint.pt \
    --output runs/probing/depth6_probes.pkl \
    --num-heads 16
```

The paths above are placeholders: replace them with real files. Model checkpoints are not included in this code release. The cached `.pkl` files in `figure_data/latents/` are intended for **plotting**; compatibility with the probe runner's reference-bundle requirements must be checked before using them as such. The consolidated probing interface has undergone synthetic-checkpoint smoke tests, but a full comparison against a historical real-checkpoint probing run remains to be performed.

## Tests

Run the automated unit tests:

```bash
python -m unittest discover -s tests -v
```

Run the separate cross-implementation grammar test (it is a standalone script, not a `unittest` test case):

```bash
python tests/test_grammar_consistency.py
```

For a small end-to-end training check:

```bash
python -m rhm_training --preset smoke \
    --train-size 128 --batch-size 32 \
    --val-size 32 --ternary-val-size 32 \
    --output runs/release_smoke/test
```

Successful small tests check that the software runs; they are not a replacement for reproducing all large-scale paper results. For a clean clone, also rerun the figure commands in [Quick start](#quick-start-reproduce-figures).

## Data and checkpoint availability

The numerical files under `figure_data/` are sufficient to regenerate the figures documented here and are intended to be committed to Git. Full trained model checkpoints and large training datasets are **not included**. Training can be reproduced with the provided scripts, subject to substantial computational requirements for the full configurations.

Only open `.pkl` and PyTorch `.pt` files from trusted sources. Both can involve unsafe deserialization if loaded incautiously.
